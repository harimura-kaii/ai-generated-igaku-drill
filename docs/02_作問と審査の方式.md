# 02 作問と審査の方式

ブループリントの1項目から問題を作り、審査し、落ちたものを作り直す仕組みの説明です。
全範囲の実行で使った版（2026-10-06.4）について書きます。そこに至るまでの試行錯誤は [版の履歴](history/versions.md) に残してあります。
モデルへ実際に送った指示文は、[prompts/](prompts/) に原文のまま置いています。

## 全体の流れ

```
生成（Opus）── 機械検査 ── 指摘出し ×4（Sonnet×2、Luna×2）── 裁定 ×2（Sonnet、Luna）
                                                                  │
                    ┌───────────── 採用 ◀── 指摘なし ──────────┤
                    │                                            │
                    │        棄却 ◀── 客観的な指摘が1つでもある ─┤
                    │                                            │
                    │        棄却 ◀── 主観的な指摘で2者が一致 ───┤
                    │                                            │
                    │      控訴審（Opus）◀── 主観的な指摘で割れた ┘
                    │         ├ 問題なし → 採用
                    │         └ 誤答が弱い／水準が違う → 棄却
                    ▼
            棄却された問題は、指摘を付けて作り直し（3周目まで）
```

## 各役と担当

| 役 | モデル | 1問あたり | 見せるもの |
|---|---|---|---|
| 生成・再生成 | Claude Opus 5.5 | 生成は3項目を1回で、再生成は1項目ずつ | 項目（知識、問える単位、水準、典拠の番号） |
| 指摘出し・水準を見せる | Claude Sonnet 5.5 | 2回 | 問題と、項目の水準・問える単位 |
| 指摘出し・水準を伏せる | GPT-6 Luna | 2回 | 問題だけ。水準は伏せる |
| 裁定 | Sonnet 5.5 と Luna | 各1回 | 問題、項目の水準・問える単位、指摘出し4回の所見、同じ項目のほかの問題 |
| 控訴審 | Claude Opus 5.5 | 割れた問題だけ1回 | 問題、項目、裁定の2者の判定 |

どの呼び出しも、過去のやり取りを持たない新しい対話です。前の段の所見や、前の周の指摘のうち必要なものだけを、指示文の中に書き込んで渡します（裁定には指摘出しの所見、控訴審には裁定の2者の判定と理由、再生成には棄却された問題とその理由）。

対象読者は、全役に共通で「解剖生理を一通り履修し終えた直後の、医学部2年生」と指定しています。

## 生成の指示の要点

全文は [prompts/1_生成.md](prompts/1_生成.md)。

**守ること3つ（優先順）**

1. 指定された水準の重さで問う。
2. 項目の内容を外さない。
3. できるだけ短く、直接に問う。

3つがぶつかったら上を優先し、原則を曲げたときは問題の `note` に理由を1行書かせます。あとで原則のほうを直すための記録です。

**水準ごとの作り方**

- **L1**: 1問1知識。状況設定は付けない。誤答は同じ種類の用語を並べれば足りる。単純でよい。
- **L2**: 機序・理由・関係を1段たどれば決まる問い。誤答は、読者が実際に持ちそうな誤解（別の機序との混同、途中の段階の取り違え、一部だけ正しい説明）から作る。正解の裏返しや、前提と露骨に矛盾する誤答は避ける。
- **L3**: 検査値や経過などを読んで当てはめる問い。必要な情報だけを置く。誤答は「その状況の別の読み方」にする。疾患名や治療は答えさせない。

そのほか、1問の中心論点は1つにする、正解だけが長さや言い回しで目立たないようにする、5つの選択肢が「1語違い」の間違い探しにならないよう共通部分は設問へ出す、既存の問題集や過去問の典型例を流用しない、などを指示しています。

正解の位置は、生成の段階では気にさせていません。あとで機械的に並べ替えています（生成された問題は、正解が A に63%偏っていました）。

## 審査の指摘の記号

| 記号 | 名前 | 中身 | 種類 |
|---|---|---|---|
| ① | 事実誤り | 正解とされた選択肢が誤り、または設問・解説に明白な事実誤認 | 客観 |
| ② | 選択肢があいまい | 複数の選択肢が正解になりうる、一意に決まらない | 客観 |
| ③ | 設問が不明瞭 | 何を問うているか読み取れない | 客観 |
| ④ | 解説が不適切 | 解説や、選択肢ごとの理由が誤り・矛盾・説明不足 | 客観 |
| ⑤ | 日本語が不適切 | 用語や言い回しが不自然、または誤用 | 客観 |
| ⑥ | 誤答が極端に弱い | 医学の知識をほとんど使わず、常識や設問との矛盾だけで複数の誤答を捨てられる。L1 の問題には適用しない | 主観 |
| ⑨ | 指定の水準と実際のずれ | 項目の水準と、実際に解くのに必要な水準が食い違う（軽すぎても重すぎても） | 主観 |
| ⑩ | 出題意図からの逸脱 | 項目の「問える単位」を実際には問えていない | 主観 |
| ⑪ | 過剰な負荷 | 解答に効かない情報、長い選択肢の突き合わせ、正解だけが形で目立つなど、知識と無関係な読解・照合・形式の手がかりが作業の中心になる | 主観（裁定のみ） |

⑦と⑧は欠番です。①〜⑤は、サイトの悪問報告の分類と同じ番号・同じ中身です。報告の分類には⑦「難しすぎる」と⑧「簡単すぎる」がありますが、これは利用者の体感を聞くもので、AI の審査では使っていません。番号を詰めずに使い続けたため、欠番になっています（⑥は、報告側では「既存の問題と酷似」、審査側では「誤答が極端に弱い」と、中身が違います）。
また、機械検査が付ける印にも「⑨-a」「⑨-b」という名前があり、これは上の⑨とは別物（設問文が正解の字面を漏らしている、正解だけ長さが違う、など）です。まぎらわしい名付けですが、実際に使った指示文なので、原文ではそのままにしてあります。

## 棄却の決まり

- **客観的な指摘（①〜⑤）**: 裁定の2者のうち、**どちらか1者でも**出せば棄却。
- **主観的な指摘（⑥⑨⑩⑪）**: 2者が**そろって**出せば棄却。**片方だけ**なら控訴審へ。
- **控訴審**: 多数決ではなく、異議の中身で裁きます。自分で問題を解き、誤答を1つずつ「知識が無いと捨てられないか」で分けたうえで、「水準が違う」「誤答が弱い」「問題なし」のどれかに決めます。問いの立て方が項目の水準どおりで、知識が要る誤答が2つ以上残っていれば「問題なし」です。
- **機械検査**: 必須の欄が欠けている、正解の記号が不正、の場合だけ機械的に落とします。字数や形式の手がかりは、落とさずに印を付けて裁定へ渡します。

## なぜこの形にしたか

**指摘出しと裁定を分けた理由。** 指摘出しには「迷ったら指摘する（見逃しのほうが高くつく）」と指示し、裁定には「根拠を持って判定する」と指示しています。広く拾う役と、絞る役を分けました。

**片方の審査員に水準を伏せた理由。** 項目の水準（たとえば L3）を先に見せると、審査員は「L3 らしく見えるか」で読んでしまいます。Luna には水準を伏せて「実際にはどの水準か」を推定させ、項目の指定と突き合わせます。症例の体裁をしていても、一対一の暗記だけで解けるなら L1 と判定させます。

**客観と主観で扱いを変えた理由。** 事実の誤りは、1人でも根拠を示して指摘したら、それで十分に疑うべきです。一方、「誤答が弱い」「水準が合わない」は審査員によって基準が揺れます。1人の意見で落とすと、厳しい審査員の好みで問題が削られます。そこで、割れたときだけ3人目に、理由の中身で裁かせます。

**生成を1段にした理由。** 当初は「出題の設計を提案する役」と「問題文に仕上げる役」の2段で、Claude Opus と GPT 系の Sol に分担させていました。内分泌の1群（23項目）で、2段（担当を入れ替えた2通り）と1段（Sol、Opus の2通り）の4条件を比べたところ、採用率の差は誤差の範囲でした。そのうえで、Sol は利用枠の消費が激しく全範囲を回すには続かないため、Opus の1段にしています。

**同じ項目のほかの問題を審査員に見せる理由。** 1つの項目から複数の問題を作るとき、1問は項目の一部だけを問うことになります。それを「出題意図を外している（⑩）」と判定されないよう、同じ項目のほかの問題の設問文と正解を裁定に見せ、項目の単位で判断させます。

## 作り直しの仕組み

棄却された問題は、その項目だけを生成の役に戻します。生成の指示文の後ろに、棄却された問題、審査員の指摘、直し方の指示、その項目ですでに採用された問題（重ねないため）を足して渡します（[prompts/2_再生成の追記.md](prompts/2_再生成の追記.md)）。
作り直した問題は、最初と同じ審査をもう一度通します。3周目でも通らなければ打ち切りです。

打ち切りは失敗ではなく、「この項目か、この切り口に無理がある」という信号として扱いました。実際に見直した結果は [04 見直しと限界](04_見直しと限界.md) にあります。

## この方式の弱点

- **審査員の誤りは、そのまま結果に入ります。** 審査員が誤って指摘すれば良い問題が落ち、見逃せば悪い問題が通ります。
- **1回通れば採用です。** 同じ問題を何度も審査すれば落ちることがある問題も、通った回で採用になります。「運よく通る」余地があります。
- **審査員が調べ物をした形跡があります。** Luna は判定の理由に論文へのリンクを付けることがあり、対象読者（医学部2年生）の水準を超えた厳密さで指摘している例があります。
- **解説の言い過ぎに弱い。** 棄却の最大の理由は、設問や正解ではなく、誤答を退ける解説の「〜だけ」「必ず」といった断定でした。作り直しても同じ型でつまずくことがあります。
